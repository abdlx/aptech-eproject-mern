# Project Status

**Project:** Lyfta Fitness Dashboard  
**Stack:** MERN-style app with Express/Mongoose backend and React/Vite frontend

## Current Status

### Frontend

- **Status:** Mostly functional with the existing backend API.
- **Location:** `frontend/`
- The static dashboard mockup has been converted into a React app with auth, dashboard data loading, workouts, nutrition, progress, reports, notifications, feedback, settings, filters, and forms.
- The frontend reads the backend URL from `frontend/.env`:

```env
VITE_API_URL=http://localhost:5000/api
```

### Backend

- **Status:** Assignment-level CRUD API.
- **Location:** `server/`
- The server was not modified during frontend integration.
- It exposes routes for auth, users, workouts, nutrition, progress, reports, notifications, and feedback.

### Database

- **Status:** Configured through environment variables, not hardcoded.
- The server connects with:

```js
process.env.MONGO_URI
```

- If `MONGO_URI` uses `mongodb+srv://`, it can connect to MongoDB Atlas.
- The current server does not create migrations.
- MongoDB databases and collections are created lazily by Mongoose after the first successful insert, such as registering a user.
- The Atlas URI should include a database name:

```env
MONGO_URI=mongodb+srv://USER:PASSWORD@cluster0.example.mongodb.net/epro_fitness?appName=Cluster0
```

## App Requirements Coverage

### Implemented Or Mostly Covered

- User registration and login
- JWT-protected API requests
- User profile fetch/update
- Workout create/read/update/delete
- Nutrition create/read/update/delete
- Progress create/read/update/delete
- Dashboard summary from workout, nutrition, and progress data
- Basic workout and nutrition filtering/search
- Report data export from backend JSON
- Notification read/delete UI
- Feedback create/read UI
- Responsive frontend layout

### Partially Covered

- Profile picture upload exists in the backend, but uploaded files are not served statically by the server.
- Reports are not generated by the backend as real PDF/CSV files. The backend returns JSON report data, and the frontend turns that data into a CSV or printable report.
- Data visualization is handled in the frontend from available progress data, not from a dedicated analytics endpoint.

### Not Fully Implemented In The Backend

- Username-based registration
- Backend-created reminders and alerts
- Backend automatic notifications for workout completion, goals, followers, or forum responses
- User search
- Followers/community/forum features
- Real PDF/CSV generation on the server
- Database migrations
- Dedicated dashboard analytics endpoint

## How To Run

### 1. Configure Server Environment

Create `server/.env`:

```env
MONGO_URI=mongodb+srv://USER:PASSWORD@CLUSTER.mongodb.net/epro_fitness?appName=Cluster0
JWT_SECRET=your_secret_key
PORT=5000
```

### 2. Configure Frontend Environment

Create or update `frontend/.env`:

```env
VITE_API_URL=http://localhost:5000/api
```

### 3. Start Backend

```powershell
cd server
node server.js
```

### 4. Start Frontend

```powershell
cd frontend
npm.cmd run dev
```

### 5. Open App

Open the frontend URL printed by Vite, usually:

```text
http://localhost:5173
```

## Important Notes

- The backend does not run migrations.
- The backend creates MongoDB collections only when data is inserted.
- The frontend is connected to the backend by `VITE_API_URL`.
- Any real MongoDB password shared in chat or committed by accident should be rotated in MongoDB Atlas.
